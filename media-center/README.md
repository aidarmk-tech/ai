# LampMedia — самостоятельный медиацентр Android TV

Отдельный APK `com.lampplayer.tv.center`, устанавливается рядом с LampPlayer. Рабочее название — LampMedia.

## Первая версия

- Нативный интерфейс с управлением пультом: каталог TMDB, фильмы, сериалы, поиск и карточки с описанием/актёрами.
- Сезоны и эпизоды → поиск раздач JacRed/Torznab → выбор файла → встроенный плеер.
- Встроенный TorrServer: запускается из установленной библиотеки APK, отдельная установка сервера не требуется.
- Избранное, история, продолжение по сохранённой позиции и автопереход при подтверждённом списке эпизодов.
- Настройки звука, субтитров и движка используют готовый LampPlayer.
- Свой канал обновлений `media-center`, независимый от `auto` плеера.

В разделе «Источники» укажи свой JacRed (адрес сервера) или полный Torznab API URL и ключ, если нужен.
Публичные адреса источников не предустановлены. Можно открыть свою magnet-ссылку/ссылку на .torrent из карточки.

## Каталоги и подборки

Кнопка «Каталог» на главной переключает TMDB, Киновод, Filmix, KinoGo KZ, KinoTac, Zona.movie и KinoKong. HTML-каталоги и карточки сайтов
разбираются нативно через jsoup; HTTP-запросы ограничены по времени/объёму и отменяются при уходе.
Подборки: новинки, новые серии, русские фильмы/сериалы, казахстанское кино/сериалы.
Фильтры стран берутся из отдельных разделов сайтов, а не из совпадения названий.
TMDB показывает премьеры/эфир и явно не выдаётся за наличие видео. Метки обновлений серий сайтов сохраняются.

В карточке можно закрепить фильм/сериал в верхнем ряду главной. Идентификаторы разных каталогов изолированы
в избранном, закреплениях, истории и сохранённых позициях; ID сайта не подставляется как TMDB ID.
Адреса зеркал меняются в «Настройки → Каталоги». Кэш списков: до 16 страниц на 2 минуты.

Проверочный онлайн доступен для Киновода, KinoGo и KinoKong; Filmix, KinoTac и Zona.movie используются как каталоги.
Для KinoKong исходный HTML читается нативно с ограничением времени/объёма. Проверяются итоговый адрес/ID карточки,
наличие `full_ID` и до трёх уникальных нетрейлерных вкладок `.newTabs`; комментарии и чужие карточки исключаются.
Метаданные загружаются в минимальном HTML-контейнере под адресом исходной карточки, без запуска рекламных/адаптивных
скриптов каталога. Видеоплееры сохраняют обычные origin/Referer. Дубли мобильной/настольной разметки не становятся
дополнительными плеерами; iframe загружается сразу. В плеере сайта выбирается видимый блок вкладок.
Диагностика различает нативное чтение HTML, число подготовленных плееров и ответы iframe; отсутствие плеера даёт отдельную ошибку.
Поддержаны объявленные плейлисты VenomPlayer/Collaps: `makePlayer`, `VenomPlayer.make`, `playlist.seasons/flat`,
`source.hls` и готовые карты `source.file`. Наблюдение не изменяет настройки/результат фабрики; read-only ES-экспорты
обрабатываются через прозрачный namespace wrapper. Заблокированные элементы, трейлерные контейнеры и недоступные
качества не становятся видео. Формат Alloha `active/all/translationList` связывает сезон/серию/озвучку с media ID;
только готовые `hlsSource` ответы для объявленного ID становятся ссылками. ID не подставляется как номер серии,
произвольные API URL/потоки не создаются. При частичных ссылках выводится явная подпись и кнопка полного списка сайта.
Диагностика добавляет имена распознанных API и счётчики declared/pending/rows без адресов/токенов.
Реальная библиотека venom-player 0.2.88 проверена в Chromium на контролируемом плейлисте; реальная карточка 95526
на публичном сервере сообщает ограничения региона обоих плееров, что не подтверждает пользовательское воспроизведение.

Для уже созданного PlayerJS восстанавливается экземпляр из известных `player/videoPlayer/pljssglobal` привязок,
включая глобальные let/const. Проверяются API id, соответствующий DOM-контейнер и отсутствие рекламной/трейлерной роли.
Чтение ограничено `id`, `playlist_folders`, `hls.url`, точным совпадением `playerConfigs.id` и единственным видеотегом
в привязанном контейнере. Восстановление не отправляет play/file/preload и не запускает скрытое видео.
Поддержаны ID с префиксом player и суффиксом хеша, либо ID, явно объявленный в playerConfigs.
Диагностика отмечает recovered/hls/config/dom. Ответ «Video Not Found ! 888» распознаётся как недоступность,
а фильм при таймауте сообщает об отсутствии ссылки, а не списка серий.
В Chromium проверена поздняя загрузка обработчика с публичной реальной сборкой PlayerJS и контролируемыми API-плеерами.
Публичный сервер для карточки 105623 получает «Video Not Found ! 888»; это не подтверждение пользовательского воспроизведения.

Трейлеры и посторонние iframe не становятся списком серий. В плеере сайта доступны кнопки трёх видеовкладок.
Нативное воспроизведение KinoKong на пользовательском соединении пока не подтверждено:
публичный сервер проверки получил региональный отказ двух плееров и нерабочий домен третьего.

Карточки TMDB предлагают «Смотреть онлайн · Киновод» параллельно торрентам.
Поиск использует локальное и оригинальное название. Автоматически выбирается только одно совпадение
названия, известного года и типа; несколько совпадений, другой год и неизвестный год требуют выбора.
Есть ручной запрос и повторный выбор источника. Подтверждённая связь сохраняется отдельно для каждого TMDB ID/типа.
Метаданные, прогресс, история и озвучка остаются под карточкой TMDB, а source_page хранит страницу Киновода.
«Продолжить» и восстановление после ошибки повторно получают выбранную серию Киновода, без передачи TMDB ID сайту.
Стабильные ключи существующего прогресса TMDB совместимы с прежними записями; идентификаторы сайтов изолированы.

Онлайн-кнопка получает метаданные плеера источника в фоне и показывает нативный выбор сезона,
озвучки, серии и доступного качества. Запуск идёт в общий LampPlayer; в плейлист попадает только
один сезон/озвучка/качество, неоднозначные номера не получают автопереход. Пропуски серий не перепрыгиваются.
Резолвер выполняет штатный JavaScript источника в невидимом WebView с запретом воспроизведения видео,
ограничением времени и без native bridge/доступа к файлам/игнорирования SSL. Нужен WebView с DOCUMENT_START_SCRIPT.
После получения списка скрытый WebView уничтожается; при уходе отменяется вся сессия.
Область резолвера ограничена выбранной страницей/ID; скрытая навигация на другой фильм блокируется.
Переадресация на каноническое название той же карточки разрешается при неизменных схеме, хосте,
порте, типе и ID; Referer воспроизведения берётся с итоговой страницы.
Контейнер источника имеет обычный viewport под непрозрачным каталогом и не получает фокус/ввод.
Перехват метаданных устанавливается до инициализации PlayerJS и учитывает передачу плейлиста через API.
Плейлист в параметрах конструктора (массив или JSON-строка) тоже учитывается. Данные основного плеера
имеют приоритет над остальными JSON-наблюдениями страницы; трейлерные плееры не используются как основной.
Выбранная на странице Filmix озвучка сохраняется в метаданных. В списке видны текущие сезон и озвучка.
После обновления истёкшей ссылки возврат из плеера восстанавливает выбранную серию и свежий список,
не расходуя предыдущий экран выбора озвучки и не отправляя повторный запрос для соседней серии.

Обработчик не обходит ограничения страны/правообладателя и не подставляет платные уровни качества.
Сохранённый обработчик Filmix учитывает доступ, сообщённый страницей текущего аккаунта; онлайн-кнопка Filmix отключена. При отсутствии доступного плейлиста
показывается ошибка; страница сайта автоматически не открывается. Ручное открытие источника остаётся
отдельной кнопкой, в том числе для входа в аккаунт. История заново получает ссылки выбранного источника;
списки кэшируются максимум на три минуты (до четырёх карточек).
Android-проверки включают реальный запуск/продвижение воспроизведения открытого HLS-примера Mux/Big Buck Bunny,
сбор метаданных через PlayerJS и обработку регионального отказа. Живой онлайн-тест Киновода пропускается
только при явном ответе о блокировке страны тестового сервера; устаревший живой онлайн-тест Filmix отключён,
его каталог и контролируемые тесты обработчика сохранены; такой пропуск не считается проверкой
воспроизведения выбранного видео. Остальные ошибки разбора/воспроизведения продолжают останавливать сборку.

Живой Android-тест читает казахстанские разделы обоих сайтов. Юнит-тесты проверяют разбор карточек,
windows-1251, метки серий, маршруты/страны/поиск, чужие ID, позиции и отклонение страниц входа.
Поиск Filmix использует штатный публичный API подсказок сайта; поиск Киновода — его HTML-выдачу.

## Качество онлайн-видео

После явного выбора качества LampMedia запоминает его отдельно для каждого поддерживаемого онлайн-источника.
Следующие серии с таким качеством открываются без повторного диалога; «Авто» тоже сохраняется.
Удержание ОК на серии или фильме открывает выбор качества. «Сбросить выбор» удаляет предпочтение
для текущего источника и ничего не запускает. Если сохранённого качества нет, даже единственный
доступный вариант требует подтверждения; отмена сохраняет прежнюю настройку.
Автоматический запуск единственного варианта без сохранённой настройки не меняет предпочтения.
Выбор ограничен качествами, которые источник предоставил текущему аккаунту.

## Интерфейс и управление

- Главная: фоновый баннер, отдельные ряды фильмов/сериалов, карточки продолжения с позицией и прогрессом.
- Активный раздел выделен в боковом меню. Вправо переводит фокус к первому действию экрана.
- Назад восстанавливает предыдущую карточку, горизонтальный ряд и прокрутку без повторного поиска.
- В карточке сериала сезоны и просмотр идут раньше описания/актёров; эпизоды слева, описание выбранного эпизода справа.
- Отдельная история; удержание ОК удаляет запись из истории, на постере каталога — переключает избранное.
- В форме источника доступен пробный запрос. Неправильный API, HTML и ошибки ключа не считаются успешным ответом.
- В настройках движка доступны запуск/остановка и кэш 32/64/128/256 МБ. Другие настройки TorrServer сохраняются.
  Изменение кэша переподключает раздачи; применяется между просмотрами. Размер кэша не равен всей памяти приложения.
- Уход с экрана отменяет HTTP-запрос. Фоновые картинки загружаются с ограниченным размером.

UI-проверки включают реальные D-pad события, переход каталог → сериал → сезон → назад и Android-рендеры четырёх экранов.
Проверка на Android 34 также меняет размер кэша через API упакованного движка и читает его обратно.

## Встроенный движок и исходный код

TorrServer MatriX.148, GPL-3.0. Лицензия включена в APK и доступна в настройках.
Исходный код соответствующей версии: https://github.com/YouROK/TorrServer/archive/refs/tags/MatriX.148.tar.gz
Проверенные SHA-256 и архитектуры зафиксированы в `engine.lock.json`.
`prepare_engine.py` загружает официальные бинарные релизы при сборке, проверяет хеш/ELF ABI и помещает их в jniLibs.
Бинарники не скачиваются приложением и не хранятся в Git. Движок привязан к 127.0.0.1, данные — в приватном каталоге приложения.
Работающий процесс сопровождается уведомлением с кнопкой остановки.

## Сборка

```sh
python media-center/prepare_engine.py
cd lampa-player-native
gradle testDebugUnitTest assembleDebug -PmediaCenter=true -PverCode=1 -PverName=0.1.1
```

CI собирает ARM APK, запускает тесты интерфейса/парсеров/истории и отдельный smoke-test
упакованного x86_64 движка на Android 34. Публикация выполняется только после обеих проверок.

Это первая рабочая версия. Проверка на конкретном ARM-телевизоре, оптимизация размера/памяти,
профили пользователей, Trakt, голосовой поиск и IPTV остаются следующими этапами; полного паритета с Flux пока нет.
