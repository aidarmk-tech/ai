# LampCore v2 — экспериментальный движок

В настройках плеера появился четвёртый режим: **LampCore — экспериментальный**.
Это собственные циклы загрузки, демультиплексирования, подачи пакетов в декодеры,
вывода PCM-звука и планирования кадров. Внутри нет ExoPlayer или libVLC.
Разбор прямых файлов делает Android MediaExtractor, HLS-контейнеров — существующие
экстракторы Media3 (TsExtractor/FragmentedMp4Extractor/AdtsExtractor).
Загрузка плейлистов, сегментов, очередь и тайминг HLS собственные;
ExoPlayer как плеер внутри LampCore не запускается. Декодирование — MediaCodec,
звук — AudioTrack. Новые нативные библиотеки в APK не добавлены.

## Возможности

- Плавность прямого файла на аппаратном видеодекодере приставки.
- Синхронизацию видео с реально проигранными аудиофреймами; опоздавшие более чем
  на 100 мс кадры отбрасываются, ранние ждут своей очереди.
- Сетевые чтения в отдельном потоке, HTTP Range, переданные из Lampa заголовки,
  паузу, перемотку, скорость 0.5–2x, переключение аудиодорожек и сохранение позиции.
- Диагностику: имя декодера, кадры, пропуски, underrun звука, очередь и скачанные байты.
- HLS master/media, относительные и перенаправленные URL, MPEG-TS, fMP4 с EXT-X-MAP,
  BYTERANGE, AES-128, фильмы с перемоткой и live с обновлением окна MEDIA-SEQUENCE.
- Предварительную загрузку следующего HLS-сегмента параллельно разбору текущего;
  отдельный загрузчик внешнего AUDIO rendition с общей временной базой.

Память HTTP-кэша ограничена 2 МиБ. Общий бюджет очередей сжатых пакетов — 4 МиБ,
плюс рабочий буфер чтения до 4 МиБ. Буферы Android-декодеров/AudioTrack выделяются
отдельно. Очереди звука и видео раздельные. При перемотке LampCore заново открывает файл
и декодеры; это медленнее специализированного seek/flush, но избегает гонок с чтением.
HLS хранит текущий и следующий сегмент каждой rendition во временных файлах:
до 16 МиБ на сегмент, init до 2 МиБ. Файлы удаляются при завершении/отмене,
ключи и init имеют небольшой ограниченный кэш. Диагностика HLS показывает
примерный объём загрузки (после AES-дешифрования).

В master первоначально выбирается самый высокий вариант не выше 1080p/8 Мбит/с;
если таких вариантов нет — самый низкий по bitrate. Затем собственный ABR оценивает
скорость фактической загрузки сегментов: снижает качество сразу, повышает после
нескольких устойчивых оценок при запасе буфера. Переключаются варианты той же
аудиогруппы и кодека, поддерживаемые декодером. Для VOD граница выравнивается по
EXTINF; для live — по PROGRAM-DATE-TIME. MEDIA-SEQUENCE разных вариантов не
считается общей временной базой. Если выравнивание невозможно, качество сохраняется.
Аппаратный adaptive AVC/HEVC получает новую CSD вместе с ключевым кадром;
остальные декодеры автоматически переоткрываются с сохранением позиции.

Временные HTTP 408/429/5xx, обрывы и таймауты повторяются с ограниченной задержкой
до двух минут. 403 и ошибки плейлиста завершаются сразу. При выходе из live-окна
движок автоматически начинает с актуального окна, примерно в трёх TARGETDURATION
от края. Отмена и перемотка прерывают запросы. Неудачная попытка загрузить плейлист
другого качества ограничена пятью секундами и сохраняет текущий вариант.

Меню дорожек показывает внешние HLS AUDIO rendition и встроенные аудиодорожки.
Начальный язык — русский, затем DEFAULT, затем первая дорожка. Выбор переоткрывает
декодеры на текущей позиции. Поддерживаются PCM16 и float, 1–8 каналов; 5.1/7.1
сводятся в стерео с центральным каналом и запасом от перегрузки. HDMI passthrough
не реализован, доступность AAC/AC3/EAC3 и других декодеров зависит от Android-бокса.

Субтитры: внешние UTF-8 SRT/WebVTT/ASS и HLS SUBTITLES WebVTT, отдельная загрузка,
X-TIMESTAMP-MAP, 33-битное переполнение PTS и discontinuity. Ошибка субтитров не
останавливает фильм. Меню позволяет выбрать/выключить дорожку; настройки — размер
и сдвиг −5…+5 секунд (плюс задерживает текст). ASS отображает текст без эффектов.

## Ограничения

- Android 6.0+; форматы и аппаратные декодеры зависят от устройства.
- Прямые файлы с поддерживаемым Android контейнером: HTTP-сервер обязан
  корректно отвечать на Range запросы (`206`, `Content-Range`, известный размер).
- Для обычного HLS Range не нужен; для BYTERANGE обязателен корректный `206`.
- DASH, SAMPLE-AES/DRM, LL-HLS без полных сегментов, delta/SKIP, GAP, смена
  кодека внутри HLS между разными MIME, встроенные bitmap/CEA/fMP4-wvtt субтитры,
  ночной режим и усиление громкости пока не реализованы. Для них используйте имеющиеся движки.
- На Android 6–9 аппаратный декодер выбирается по имени/возможностям; это эвристика.
  На Android 10+ используется `isHardwareAccelerated`. Имя всегда видно в диагностике.
- Совместимость Filmix и улучшение плавности ещё не подтверждены на приставке.
  Если проблема в контейнере/аудиокодеке, которых нет в Android, следующим этапом
  нужен минимальный libavformat/аудиодекодер. LampCore их не содержит.
- APK всё ещё содержит существующий libVLC для сравнения. Уменьшение размера APK
  и увеличение скорости данным изменением не заявляются.

## Сборка и проверка

GitHub Actions **Build LampCore preview** запускает `testDebugUnitTest assembleDebug`.
Тесты проверяют HTTP Range/seek/EOF, сохранение заголовков, отказ при неверном диапазоне,
отмену зависшего запроса, переполнение счётчика AudioTrack и планирование кадров.
HLS-тесты проверяют парсинг master/media, выбор качества, live-окно, AES-128,
init+BYTERANGE, а также реальный разбор синтетических TS/fMP4 фрагментов в Robolectric,
непрерывность временных меток, seek по сегментам и отдельное аудио. Новые тесты
проверяют retry/cancel, обрыв сегмента без дублирования байтов, ABR с реальной
сменой разрешения, восстановление live, две встроенные AAC-дорожки, PCM-downmix
и внешние/HLS WebVTT-субтитры, задержку, выключение и временные карты.

Артефакт `LampCore-preview-<номер>` содержит APK и отчёт тестов. Сборка с
`-PlampCorePreview=true` получает отдельный applicationId `com.lampplayer.tv.lampcore`
и название **LampPlayer · LampCore**, чтобы её можно было установить рядом с основной.
Автообновление из основной release-ленты в этой сборке отключено. По умолчанию
движок остаётся `auto`: LampCore нужно явно выбрать в настройках тестового приложения.

1. Установите preview APK, откройте настройки и выберите LampCore; включите диагностику.
2. В Lampa выберите этот внешний плеер через системный выбор приложений. Если плагин
   жёстко задаёт пакет, для теста нужен `com.lampplayer.tv.lampcore`, activity
   `com.lampplayer.tv.player.PlayerActivity`; основную настройку менять не обязательно.
3. Сначала проверьте обычный MP4 и HLS (H.264 + AAC mono/stereo), затем проблемный источник.
4. Проверьте старт, паузу/возобновление, перемотку вперёд/назад, дорожки, скорость,
   смену фильма и возврат позиции в Lampa. Сравните тот же поток с ExoPlayer и VLC.
5. Запишите модель приставки, имя декодера и показатели за минуту. Рост underrun и
   пустая очередь указывают на нехватку данных/сбой подачи; пропуски при заполненной
   очереди требуют проверки декодирования, таймингов и частоты экрана.

Без испытания на Android-устройстве успешная сборка не доказывает воспроизведение.
