# LampCore v1 — экспериментальный движок

В настройках плеера появился четвёртый режим: **LampCore — экспериментальный**.
Это собственные циклы загрузки, демультиплексирования, подачи пакетов в декодеры,
вывода PCM-звука и планирования кадров. Внутри нет ExoPlayer или libVLC.
Разбор контейнера делает Android MediaExtractor, декодирование — MediaCodec,
звук — AudioTrack. Новые нативные библиотеки в APK не добавлены.

## Что проверяет прототип

- Плавность прямого файла на аппаратном видеодекодере приставки.
- Синхронизацию видео с реально проигранными аудиофреймами; опоздавшие более чем
  на 100 мс кадры отбрасываются, ранние ждут своей очереди.
- Сетевые чтения в отдельном потоке, HTTP Range, переданные из Lampa заголовки,
  паузу, перемотку, скорость 0.5–2x, переключение аудиодорожек и сохранение позиции.
- Диагностику: имя декодера, кадры, пропуски, underrun звука, очередь и скачанные байты.

Память HTTP-кэша ограничена 2 МиБ. Общий бюджет очередей сжатых пакетов — 4 МиБ,
плюс рабочий буфер чтения до 4 МиБ. Буферы Android-декодеров/AudioTrack выделяются
отдельно. Очереди звука и видео раздельные. При перемотке v1 заново открывает файл
и декодеры; это медленнее специализированного seek/flush, но избегает гонок с чтением.

## Границы v1

- Android 6.0+; форматы и аппаратные декодеры зависят от устройства.
- Только прямые файлы с поддерживаемым Android контейнером. HTTP-сервер обязан
  корректно отвечать на Range запросы (`206`, `Content-Range`, известный размер).
- HLS/DASH, DRM, субтитры, многоканальный PCM, ночной режим и усиление громкости
  пока не реализованы. Для них используйте имеющиеся движки.
- На Android 6–9 аппаратный декодер выбирается по имени/возможностям; это эвристика.
  На Android 10+ используется `isHardwareAccelerated`. Имя всегда видно в диагностике.
- Совместимость Filmix и улучшение плавности ещё не подтверждены на приставке.
  Если проблема в контейнере/аудиокодеке, которых нет в Android, следующим этапом
  нужен минимальный libavformat/аудиодекодер. v1 их не содержит.
- APK всё ещё содержит существующий libVLC для сравнения. Уменьшение размера APK
  и увеличение скорости данным изменением не заявляются.

## Сборка и проверка

GitHub Actions **Build LampCore preview** запускает `testDebugUnitTest assembleDebug`.
Тесты проверяют HTTP Range/seek/EOF, сохранение заголовков, отказ при неверном диапазоне,
отмену зависшего запроса, переполнение счётчика AudioTrack и планирование кадров.

Артефакт `LampCore-preview-<номер>` содержит APK и отчёт тестов. Сборка с
`-PlampCorePreview=true` получает отдельный applicationId `com.lampplayer.tv.lampcore`
и название **LampPlayer · LampCore**, чтобы её можно было установить рядом с основной.
Автообновление из основной release-ленты в этой сборке отключено. По умолчанию
движок остаётся `auto`: LampCore нужно явно выбрать в настройках тестового приложения.

1. Установите preview APK, откройте настройки и выберите LampCore; включите диагностику.
2. В Lampa выберите этот внешний плеер через системный выбор приложений. Если плагин
   жёстко задаёт пакет, для теста нужен `com.lampplayer.tv.lampcore`, activity
   `com.lampplayer.tv.player.PlayerActivity`; основную настройку менять не обязательно.
3. Сначала проверьте обычный прямой MP4 (H.264 + AAC stereo), затем проблемный источник.
4. Проверьте старт, паузу/возобновление, перемотку вперёд/назад, дорожки, скорость,
   смену фильма и возврат позиции в Lampa. Сравните тот же поток с ExoPlayer и VLC.
5. Запишите модель приставки, имя декодера и показатели за минуту. Рост underrun и
   пустая очередь указывают на нехватку данных/сбой подачи; пропуски при заполненной
   очереди требуют проверки декодирования, таймингов и частоты экрана.

Без испытания на Android-устройстве успешная сборка не доказывает воспроизведение.
